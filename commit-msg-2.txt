demo: make the vocoder page a Vite entry so it bundles ONNX Runtime

The static page shipped in the previous commit loaded the runtime from
../ort/ort.wasm.min.mjs, which 404s in production: public/ort/ is in .gitignore
(the main app gets the runtime from Vite's bundling, not from a public copy), so
the first live check showed the page reachable but its runtime missing.

Fix: vocoder.html is now a second Vite entry (build.rollupOptions.input) and
imports onnxruntime-web exactly like src/engine.ts does, so Vite emits the
runtime JS and the 28 MB WASM as hashed same-origin assets. The page, the mel
dumps and the model stay fetchable as relative URLs, which matters because GitHub
Pages serves the site from a sub-path.

  dist/vocoder.html                          2.78 kB
  dist/assets/vocoder-*.js                   3.15 kB
  dist/assets/ort.bundle.min-*.js          413.68 kB
  dist/assets/ort-wasm-...-jsep-*.wasm      28.3 MB
  no CDN, no absolute /ort/ reference

scripts/check-vocoder-page.mjs now checks the entry (7 relative URLs, 0 missing,
resolving ./public/... as a bundled source module) and still verifies the
inference path against PyTorch: hz-001..004 corr 0.999999053 / 0.999999354 /
0.999998886 / 0.999999385, 158-385 ms per sentence under WASM.
