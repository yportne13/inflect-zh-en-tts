demo: real in-browser vocoder page (public/vocoder/)

The deployment requirement was only proven by Node checks so far. This adds an
actual page that renders 24 kHz audio in the browser from a real recording's
100-band log-mel, using our own 6.7M vocoder as vocoder-fp16.onnx (18.25 MB)
through onnxruntime-web's WASM backend:

  public/vocoder/index.html        UI: render live, plus the real recording and
                                   the Vocos rendering as reference anchors
  public/vocoder/vocoder-infer.mjs DOM-free inference, shared with the check
  public/vocoder/mel/*.f32         4 held-out mels + PyTorch reference waveforms
  scripts/check-vocoder-page.mjs   runs the page's own module under ort-web and
                                   compares against those references

  page refs : 6 relative URLs, 0 missing  (relative, because Pages serves from a
                                           sub-path -- absolute paths 404 there)
  hz-001..004: corr 0.999999053 / 0.999999354 / 0.999998886 / 0.999999385
  render time in WASM: 171-353 ms per sentence

Writing this check caught a real mismatch immediately: the reference waveforms
came from the step-6000 checkpoint while the shipped ONNX was the step-4000
export, so the correlation was 0.26 -- the graph was re-exported from the current
checkpoint and now matches. npm run check:page re-runs it.
